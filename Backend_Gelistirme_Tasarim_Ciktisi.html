1. Proje Tanımı, Kapsamı ve İş Senaryosu

1.1 Projenin Amacı

Bu projenin temel amacı; modern yazılım geliştirme şirketlerinin ve ekiplerinin çoklu departmanlar (Frontend, Backend, DevOps, QA, Mobil, UI/UX) genelinde yürüttükleri iş ve görev süreçlerini merkezi, güvenilir, ölçeklenebilir ve yüksek performanslı bir RESTful API arka uç (backend) sistemi ile yönetebilmelerini sağlamaktır.

Proje; Node.js çalışma ortamında asenkron I/O işleme, Express.js çatısıyla modüler yönlendirme (routing), Katmanlı Mimari (Controller, Service/Model, Middleware) kurgusu, atomik dosya tabanlı JSON veri depolama ve katı girdi doğrulama prensiplerini eksiksiz somutlaştırmaktadır.

1.2 Şirket Senaryosu ve Çözülen İş İhtiyaçları

Kurumsal Senaryo: Çok disiplinli 50+ mühendis barındıran bir teknoloji şirketinde, sprint işlerinin dağıtımı, ilerleme takibi ve yönetimsel raporlama süreçlerinin tekilleştirilmesi hedeflenmiştir.
İş Problemi Sistemin Sağladığı Çözüm Uç Nokta / Bileşen
Görev Dağıtımı Proje yöneticilerinin dinamik olarak iş oluşturabilmesi, öncelik ve geliştirici atayabilmesi. POST /tasks
Durum Takibi Geliştiricilerin iş ilerlemesini (pending ➔ in_progress ➔ completed) anlık güncellemesi. PUT /tasks/:id
Öncelik Yönetimi Kritik ve yüksek öncelikli blocker işlerin anında filtrelenebilmesi. GET /tasks?priority=high
Hızlı Arama & Filtreleme Yüzlerce görev arasında anahtar kelime, durum veya çalışan bazında milisaniyelik filtreleme. GET /tasks/search, GET /tasks/assignee/:assignee
Yönetimsel Raporlama Tamamlanan ve bekleyen görev sayıları ile departman bazlı iş dağılımının tek tıkla özetlenmesi. GET /reports/summary
Denetim ve İzlenebilirlik Gelen tüm HTTP isteklerinin zaman damgası, IP ve süre bazında kalıcı kütüğe yazılması. logs/access.log (Logger Middleware)

2. Sistem Mimarisi ve Tasarım İlkeleri

TaskFlow REST API, yazılım mühendisliğinde kabul görmüş Katmanlı Mimari (Layered Architecture) ve Sorumlulukların Ayrılması (Separation of Concerns) prensiplerine göre yapılandırılmıştır.

2.1 Mimari Akış Şeması

2.2 Katmanların Görev Dağılımı

  • Ara Yazılım (Middleware) Katmanı: İstek yönlendiriciye ulaşmadan önce CORS başlıklarını ayarlar, JSON gövdelerini parse eder, her isteği logs/access.log dosyasına yazar ve veri ekleme/güncelleme rotalarında şema kurallarını doğrular.
  • Yönlendirme (Routing) Katmanı: REST standartlarına uygun uç noktaları (/tasks ve /reports) mantıksal gruplara ayırır, URI yapısını yönetir.
  • Denetleyici (Controller) Katmanı: HTTP istek nesnesini (req) alır, parametreleri işler, Model katmanından gelen verileri formatlayarak HTTP durum kodlarıyla (res) yanıt döner.
  • Model (Veri Erişim) Katmanı: JSON tabanlı veri tabanına doğrudan asenkron dosya okuma ve yazma işlemlerini yürütür. İş mantığı, filtreleme, arama ve sayfalama algoritmaları bu katmanda soyutlanmıştır.

2.3 İstek Yaşam Döngüsü (Request Lifecycle)

Gelen her HTTP isteği sırasıyla: cors() ➔ express.json() ➔ loggerMiddleware ➔ express.Router ➔ (varsa) validationMiddleware ➔ Controller ➔ Model ➔ JSON Storage hattından geçer. Yanıt dönüş yolunda merkezi errorHandler hata yakalamasını garanti eder.

3. Veri Modeli ve Varlık Tasarımı (Data Design)

3.1 Görev Varlığı (Task Entity) Şeması

Sistemin temel veri varlığı Task nesnesidir. Bir görev nesnesinin sahip olduğu tüm alanlar, veri tipleri ve kısıtları aşağıdaki tabloda standardize edilmiştir:

Alan Adı Veri Tipi Zorunlu Varsayılan Kısıtlar & Kurallar Açıklama

title String Evet - 3 - 100 karakter arası metin Görevin kısa ve net başlığı
description String Evet - 5 - 500 karakter arası metin Görevin detaylı iş tanımı

4. RESTful API Tasarımı ve Uç Noktalar Envanteri

Sistem, HTTP metotlarının anlamsal (semantik) doğrulukla kullanıldığı eksiksiz bir RESTful uç nokta envanterine sahiptir.

Metot Uç Nokta (Path) Modül / Kategori Beklenen Parametre Başarı Kodu İşlev Özeti
GET / Sistem Bilgisi Yok 200 OK API servis durumu, çalışma süresi ve servis dizini
POST /tasks Zorunlu CRUD JSON Body (title, desc, priority, assignee) 201 Created Yeni görev oluşturur (Validation devrededir)
GET /tasks Zorunlu CRUD Query: status, priority, page, limit, sort 200 OK Görev listesi döner (Filtreleme, Sıralama, Sayfalama)
GET /tasks/:id Zorunlu CRUD Path: :id 200 OK / 404 Belirtilen ID'ye ait görevin detayını getirir
PUT /tasks/:id Zorunlu CRUD Path: :id, JSON Body 200 OK / 404 Mevcut görevi günceller (status, priority vb.)
DELETE /tasks/:id Zorunlu CRUD Path: :id 200 OK / 404 Belirtilen görevi veritabanından kalıcı olarak siler
GET /tasks/search Gelişmiş API Query: ?keyword=... 200 OK Başlık, açıklama ve projede büyük/küçük harfsiz arar
GET /tasks/assignee/:assignee Gelişmiş API Path: :assignee 200 OK Belirli bir çalışanın üzerine atanmış görevleri döner
GET /reports/summary Raporlama Yok 200 OK Tamamlanma oranı, öncelik ve proje dağılım istatistiği
GET /reports/completed Raporlama Yok 200 OK Yalnızca tamamlanan görevlerin toplamı ve listesi
GET /reports/pending Raporlama Yok 200 OK Yalnızca bekleyen görevlerin toplamı ve listesi
POST /tasks/reset Test Yardımcısı Yok 200 OK Test veritabanını varsayılan tohum verilerine döndürür

4.1 Standart HTTP Yanıt Formatı

Tüm uç noktalar tutarlı ve tahmin edilebilir bir JSON şablonu ile yanıt döner:

Başarılı Yanıt (200 OK / 201 Created):

{
  "success": true,
  "statusCode": 201,
  "message": "Görev başarıyla oluşturuldu.",
  "data": { ... }
}

Hata Yanıtı (400 Bad Request / 404 Not Found):

{
  "success": false,
  "statusCode": 400,
  "message": "Doğrulama hatası...",
  "errors": [ { "field": "title", ... } ]
}

5. Ara Yazılım (Middleware) ve Güvenlik Mimarisi

5.1 Logger Middleware (Zaman Damgalı Günlükleme)

Eğitimin zorunlu isterleri arasında yer alan temel Logger ara yazılımı (src/middlewares/loggerMiddleware.js), gelen her HTTP isteğini dinler:

  • İsteğin zaman damgasını (ISO 8601 formatında), HTTP metodunu, hedef URL yolunu ve istemci IP'sini yakalar.
  • Yanıt döndüğünde harcanan süreyi milisaniye (ms) cinsinden hesaplar.
  • Terminal konsoluna HTTP durum koduna göre renklendirilmiş (2xx Yeşil, 4xx Sarı, 5xx Kırmızı) log yazar.
  • Aynı log kaydını kalıcı olarak logs/access.log dosyasına güvenli şekilde senkron/append eder.
[2026-11-15T11:20:00.000Z] POST /tasks 201 12ms - ::1
[2026-11-15T11:20:05.000Z] GET /tasks?priority=high 200 4ms - ::1
[2026-11-15T11:20:10.000Z] GET /tasks/999999 404 2ms - ::1

5.2 Gelişmiş Validation Middleware (İsteğe Bağlı İleri Pratik)

Görev oluşturma (POST /tasks) ve güncelleme (PUT /tasks/:id) operasyonlarında istek gövdesinin bütünlüğünü denetler:

  • title: Boş bırakılamaz, string tipinde ve en az 3 karakter olmalıdır.
  • description: Boş bırakılamaz, en az 5 karakter olmalıdır.
  • priority: low, medium, high, critical değerlerinden biri olmak zorundadır.
  • assignee: Atanan çalışan adı zorunludur ve en az 2 karakter olmalıdır.
  • Kural ihlali durumunda işlem denetleyiciye aktarılmadan anında HTTP 400 Bad Request ve ayrıntılı hata listesiyle sonlandırılır.

5.3 Merkezi Hata Yönetimi (Error Handler)

Sistemde tanımlı olmayan rotalara erişim sağlandığında HTTP 404 Not Found JSON formatında standartlaştırılmıştır. Beklenmeyen sunucu içi istisnalarda ise HTTP 500 Internal Server Error istemciye zarif bir hata mesajı iletilirken sunucunun çökmesi engellenir.
